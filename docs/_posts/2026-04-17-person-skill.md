资料收集 -> 按主题检索 -> 填入固定格式, 生成skill

## 具体实现步骤

### 第一步：资料来源图谱（Source Data Map）

| 资料分类       | 具体来源                          | 获取手段                  | 保存方式                           |
| :--------- | :---------------------------- | :-------------------- | :----------------------------- |
| **公众公开资料** | 著作、博客、访谈、YouTube、X/微博、论文      | RSS、Web Agent、YT 转文字  | **按信源属性** (如 `01-writings.md`) |
| **职场数字资产** | 飞书/钉钉文档、周报、Slack 消息、Email     | 企业 API、Bot、邮件导出       | **按功能分层** (如 `work.md`)        |
| **私人即时通讯** | 微信、iMessage、WhatsApp、Telegram | `WeChatMsg`、SQLite 导出 | **按日期/快照** (如 `snapshot.json`) |
| **个人生活记忆** | 备忘录、手机相册 (OCR)、日记、生平年表        | 手动导入、手机备份提取           | **按语义 Slug** (如 `memory.md`)   |
| **主观观察补丁** | 熟人口述、你的评价、性格标签 (INTJ)         | 人类主观录入                | **动态修正层** (如 `correction.md`)  |

### 第二步：按主题检索（Theme-based Retrieval）

利用大模型的推理能力进行 **“语义解构”**。检索过程由 Skill 指令进行全流程约束。由Agent 根据环境自主选择
- 拆解成sub-agent处理不同主题
- 编写/调用代码分析语料库的特征(频率等)
- 关键词提取: `grep`（硬匹配）或 `Semantic Search`（chunking/向量embedding/RAG模型）
来实现目标.

**这也是不同框架的最主要区别**. 另外, 也可以让agent自主决定主题(多半会是从高频内容提取).

| 框架                 | 核心检索主题                                           | 检索关键词(显示指定/agent自发联想)              | 特殊检索规则与校验逻辑                                                             |
| :----------------- | :----------------------------------------------- | ---------------------------------- | :---------------------------------------------------------------------- |
| **Nuwa (女娲)**      | 带有 “定义行为” 的上下文                                   | 我认为、原则是、关键在于、自创术语                  | **三重验证法**：必须跨域复现（≥2 个场景出现）、具有预测力、且具备排他性（非通用常识）。                         |
| **Immortal (永生)**  | 消息密度变化(那些聊天记录里“你来我往”频率最高的片段)<br>认知突变, 情感极值, 叙事中心 | 后悔、终于、记得、从那以后、痛苦、最高兴、发现、[时间/地点/人物] | **证据分级制**：检索结果强制打标 `verbatim` (原话)、`artifact` (文档) 或 `impression` (他评)。 |
| **Colleague (同事)** | 用户主观标签(翻译表)<br>职场黑话                              | 对齐、赋能、抓手、Impact、闭环、需求没说清楚          | **优先级纠偏**：用户手动标签优先级高于文件分析结论；通过“修正层”实时覆盖检索偏差。                            |
| **Qiushi (求是)**    | 原著章节标题                                           | 主要矛盾、调查、实践、反馈、路线                   | **原著锚定法**：检索结果必须严格对齐内置的“真理底座”；通过 Hook 在会话开始时强制注入。                       |


### 第三步：填入固定格式（Templating）

检索出的“主题语料包”依然是零散的。填入固定格式的目标是进行 **归纳与降噪（Synthesis & De-noising）**，将素材按照不同框架预设的 **认知容器（Cognitive Containers）** 进行归位：

| 框架                 | 核心容器 (Template Structure)                   | 提炼重点&抽象归纳                                           |
| :----------------- | :------------------------------------------ | :-------------------------------------------------- |
| **Nuwa (女娲)**      | **5 层认知 OS**：心智模型、决策启发式、表达 DNA、反模式、诚实边界。    | 将具体案例抽象为可通用的思维算法（HOW they think）。                   |
| **Immortal (永生)**  | **4D 数字灵魂**：程序性知识、互动风格、记忆经历、性格价值观。          | 保留生平故事细节，追求“记忆重现”。                                  |
| **Colleague (同事)** | **A/B 双核结构**：PART A (工作能力) + PART B (人物性格)。 | 侧重于“任务接收 $\rightarrow$ 性格过滤 $\rightarrow$ 业务执行”的链路。 |
| **Qiushi (求是)**    | **方法论工具箱**：9 大思想武器（如矛盾分析、持久战略）。             | 将思想转化为可执行的skill与专项子 Agent。                          |


## 总结和反思

- 所谓“蒸馏”某个人, 是从个人语料提取/抽象的一些风格化的表达方式或方法论. 然后用agent cosplay这个人. 但是没法保存具体的知识. 
- 那么模仿普通人, 是否能达到周围人都看不出来的效果呢?
- 其实我越想越觉得确实可行😮‍💨 , 诚实地说很多人的观点/性格/对话模式本来就是由环境注入(不是塑造)的, 在生活中就像npc一样.  好像通过话语不多的skill让认知更高的agent模仿完全可行啊. 网络诈骗, 看不出来的人不是很多吗. 难的反倒是说话的一些习惯和细节, 但是这貌似也是可以建模的.
